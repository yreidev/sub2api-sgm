# SGM 简洁首页 · 浅色设计规范

本规范适用于账户概览、接入助手及其充值弹窗。设计依据是 IBM Carbon 对产品字体层级、色彩分层和间距的定义。SGM 采用 IBM Plex 字体，使用雾白、墨青与浅青灰组织界面；色值、余额纹样、圆角和响应式布局均为本产品取值。[Carbon 字体规范](https://www.carbondesignsystem.com/building-blocks/foundations/typography/type-sets) · [色彩与层次](https://www.carbondesignsystem.com/building-blocks/foundations/color/overview) · [间距表](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)

## 字体与数字

英文、数字使用本地加载的 IBM Plex Sans。中文依次使用 PingFang SC、Microsoft YaHei、Noto Sans CJK SC 和系统无衬线字体。API 地址、密钥、模型 ID 使用 IBM Plex Mono。IBM Plex 字体资源随应用分发，用户打开页面时无需请求外部字体服务。

| 内容 | 字号 / 行高 | 字重 | 使用方式 |
| --- | --- | --- | --- |
| 页面标题 | 桌面 36 / 44 px，手机 28 / 34 px | 500 | 每页一个一级标题，左侧与余额和接入面板对齐 |
| 可用余额 | 36–56 px / 1.12 | 500 | 等宽数字，保留币种符号及原金额精度，允许长金额换行 |
| 接入区、弹窗标题 | 24 / 32 px | 500 | 页内主要任务 |
| 充值步骤 | 17 / 25.5 px | 600 | 数字表示实际操作顺序 |
| 接入说明 | 16 / 26 px | 400 | 中文长句留足行距 |
| 字段标签、充值步骤说明 | 15 / 24 px、15 / 22.5 px | 500、400 | 标签在输入框上方，简短提示跟随相应字段 |
| 地址、模型、密钥 | 14 px，移动端输入控件可达 16 px | 400 | 等宽字体，已领取的密钥常显并换行 |
| 金额选项 | 数值 17 px，币种及档位明细 13 px | 600、400 | 数值与 CNY、USD 用字号和字重区分 |

## 浅色用色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 页面底色、面板 | `#F6F8F8`、`#FFFFFF` | 背景后退半层，表单保持白底 |
| 主文字、辅助文字 | `#192E38`、`#52676E` | 标题、金额与帮助文案；与白底对比分别约 14.1∶1、6.0∶1 |
| 主操作、悬停、键盘焦点 | `#195762`、`#124751`、`#126C7A` | 白字主操作对比约 8.1∶1 |
| 分区边线 | `#D6E0E1` | 导航、面板和账单的分隔 |
| 字段底色、字段边线 | `#F8FAFA`、`#819496` | 输入、下拉及可选金额；边线与字段底色对比约 3.0∶1 |
| 已选金额、结算面板 | `#EDF6F5`、`#F4F8F7` | 单选项用浅底加双线，结算明细用浅底分组 |
| 禁用付款 | `#E7EEEF` 底、`#52676E` 字 | 保留可读性，按钮文字说明禁用原因 |

余额卡使用低饱和渐变与原创的细线波纹，占用卡片右侧空间。文字、余额和充值按钮位于左侧；移动端纹样进一步淡化。简洁页固定浅色，包括菜单、帮助图和充值订单状态。离开简洁页恢复进入前的界面主题。

## 访客入口与认证

默认访客主页展示站点品牌、登录和开放注册时的创建账户入口，再介绍模型接入、账户余额和请求明细。精简模式收起功能介绍。管理员指定的自定义首页 HTML 或 URL 优先显示。登录、注册、邮箱验证、找回密码及共用认证布局的回跳页沿用相同的品牌栏、字体、表单和主题切换。

主页中的模型广场入口遵循公开访问开关。独立广场共用主页品牌栏、语言及主题切换，通过品牌链接返回主页。访客可搜索模型，按平台、分组和倍率筛选，窄屏可横向浏览价格表。普通账号登录后进入简洁首页，也可以打开模型广场浏览可见分组并通过顶栏入口返回简洁首页；管理员可在后台嵌入模式浏览广场。

价格表用两档上下文价格、同时含 1h 和 12h 的缓存写入价验收。在 1054 px 的桌面表格中，`gpt-6.2-astra` 应占一行，最右侧倍率应完整可见。手机上分别切换浅色和深色，横向滑到倍率列时，模型列应保持固定，用不透明底色遮住滑过的价格。两档的输入、输出和缓存价分别对齐。

注册设置由服务端决定。关闭注册时提供登录入口，设置读取失败时可就地重试。邮箱验证开启时先完成验证码步骤，再进入账户概览。用户端的按钮、输入框、选择器、语言菜单、弹窗和请求详情使用 HeroUI。Vue 负责路由和业务状态。路由链接、语义卡片和包含合并单元格的价格表复用 HeroUI 官方组件样式，表单保留自动填充、浏览器校验和输入法组合输入。

## 布局与空间

- 内容最大宽度 1056 px。桌面页首留白 48 px，卡片间距 24 px，卡内留白 32 px；手机页面两侧留 16 px，卡内 20 px。
- 余额横幅占满内容宽度，「自助充值」与「刷新余额」紧邻数值。充值使用实心按钮，刷新使用带图标的文字按钮。
- 桌面接入区左侧放接入说明和「复制接入信息」，右侧放模型、API 基础地址和密钥。小于 800 px 时按标题、字段、整组复制的顺序单列排列。
- 接入助手面向 OpenAI Chat Completions 客户端。用户复制以 `/v1` 结尾的基础地址，客户端负责构造请求路径。助手只列出 Auto 分组的 Chat 模型，整组复制包含模型、基础地址和密钥。
- 使用概览位于接入区之后，是首页最后一张卡片。今日实际消耗、请求数和 Token 用量按浏览器时区统计。下方列出最近五次调用的模型、时间和实际费用，「查看全部」在本页按每页 20 条展示历史记录。每条请求都可展开查看请求 ID、接口、耗时、输入输出及缓存 Token、实际费用。
- 使用记录整行可点击。桌面按模型、时间、费用、详情四列对齐。手机第一行展示模型和费用，第二行展示时间和详情。
- 普通账号的控制台固定为简洁首页，可打开模型广场并返回简洁首页，访问其他后台地址时返回首页。只有管理员可以预览简洁首页并切回后台。认证授权和支付回跳保留各自的流程。后台接口根据服务端会话角色校验权限。首页使用记录和订单按登录账号查询，外部 MCP 继续按其授权范围执行。
- 充值提交结果不明时，在充值弹窗中按每页五笔查询自己的订单，核对编号、时间、金额和状态。查询失败可就地重试。
- 充值弹窗最大宽度 960 px。宽屏左侧选金额，右侧选方式和核对账单。小于 800 px 时依阅读顺序堆叠。手机正文可独立滚动，标题和关闭按钮始终可见。
- 面板圆角 18 px，表单和操作圆角 10 px，弹窗圆角桌面 20 px、手机 16 px。导航、钱包和复制操作使用 Lucide 线性图标，正文操作图标 16–18 px，面板图标 22 px。图标旁保留操作名称。关键按钮和选项触控高度至少 44 px。

## 控件与文案

| 场景 | HeroUI 官方组件 | 行为 |
| --- | --- | --- |
| 账户与余额 | Surface、Card、Typography、Button、Dropdown | 签入后查看和刷新余额，管理员可从账户菜单返回管理后台 |
| 模型 | Select、ListBox、Label、Description | 加载账号实际可用的模型，Astra 优先；键盘可选，失败时可重试 |
| API 地址与密钥 | TextField、InputGroup、TextArea、Button | 单项复制始终有文字按钮；三项就绪时支持整组复制，剪贴板受限时提供手动复制 |
| 充值 | Modal、ToggleButton、Chip、TextField、FieldError | 先选金额，再选支付方式，最后核对实付和预计到账；自定义金额支持数字键盘，错误出现在字段旁 |
| 支付反馈 | Card、Alert、Spinner、Toast | 区分已付款、到账处理中和充值到账；关窗保留所选金额与订单，刷新可恢复同账号订单 |

人民币渠道的说明同时写出「人民币（CNY）」和「美元（USD）」。快捷档位保留付款币种与优惠信息；核对区把实付、费用或赠送、到账金额列为独立行。预览环境在禁用操作上写明付款停用。[HeroUI 弹窗](https://heroui.com/en/docs/react/components/modal) · [HeroUI 输入组](https://heroui.com/en/docs/react/components/input-group)

## 验收

用 320、390、412、768 和 1280 px 宽度检查菜单、长密钥、金额、币种及弹窗滚动。键盘打开菜单和弹窗后应可选择和关闭，焦点回到触发按钮。使用模拟订单验证重开、刷新、后台查询及到账状态。对外演示图使用示例余额、示例地址和演示密钥。

## 评审记录

| 优先级 | 初版评审发现 | 修复后的行为 |
| --- | --- | --- |
| P1 | Stripe 和 Airwallex 渠道页找不到简洁页订单的付款参数。 | 按当前账号与订单读取快照，核对回跳提供的恢复令牌和商户订单号。登录用户发起付款前再向服务端确认订单归属和待付款状态。 |
| P1 | 已扣款但入账失败的订单可能被清除，用户可能再次付款。 | `FAILED` 且有 `paid_at` 时保留订单，显示「已扣款，入账失败」、查单按钮和可提供给管理员的订单号。 |
| P2 | 余额刷新失败会掩盖到账确认。 | 收到 `COMPLETED` 即确认到账、清除对应快照并重置金额。余额请求单独反馈，用户可在首页点「刷新余额」重试。 |
| P2 | 恢复全额退款订单时无法退出旧订单。 | 恢复或轮询到 `REFUNDED` 时显示「已退款」并停止等待。点「返回选择金额」后清除快照并恢复原档位。 |
| P2 | 待恢复快照清除后，管理员预览的订单结果页失去简洁页入口。 | 在当前浏览器按账号和订单保存入口标识，只记录订单编号。结果页按服务端返回的订单识别来源，刷新后仍可返回首页。 |
| P2 | Auto 没有可服务的模型时，助手仍可能预选静态目录里的模型。 | 助手模型目录按可调度账号、Chat Completions 路由及分组白名单计算，为空时返回空数组。Codex 清单继续使用原有回退。 |
| P2 | 登录页和后台首屏预加载了 HeroUI、React Aria。 | HeroUI 运行时按使用组件的路由加载。登录页现在使用 HeroUI，管理后台入口仍独立。验收检查生产 HTML 的模块预加载、主入口的静态依赖和浏览器的实际请求。 |
| P3 | 微信 OAuth 回跳下单后，界面恢复的金额变成零。 | 回跳保留授权前选的金额，用于显示和恢复档位。签名令牌提供下单金额，回退到二维码时也随请求传递。 |

浏览器模拟验收已覆盖 Stripe 和 Airwallex 渠道交接、已扣款订单补入账、退款后返回原金额、余额刷新失败后手动重试，以及管理员刷新支付结果页后返回简洁页。独立浏览器会话也验证了普通用户和管理员的访问范围，首页底部的请求详情、分页与收起均可在本页完成。支付渠道使用模拟响应，未发起真实交易。

生产构建的入口 HTML 只预加载 Vue 和国际化模块。检查 Rollup 输出的静态依赖图，并分别打开登录页、管理后台和简洁页核对网络请求，确认主页、认证页、模型广场和简洁页按需加载 HeroUI，管理后台首屏不预加载它。微信签名回跳、退款终态、空模型目录和常规 Codex 清单回退均有自动化回归用例。
